# 📋 Табель 2.0 — учёт рабочего времени и выплат

Система из двух приложений: мобильное для сотрудника и настольное для руководителя.
Сотрудник ведёт учёт дня на телефоне, руководитель видит все записи, утверждает их,
строит графики и печатает ведомости. Обмен данными — через облачный сервер
(Google Apps Script + Google Sheets), поэтому телефон и компьютер не должны
находиться в одной сети.

## 🎯 О проекте

Проект заменяет бумажную «Карточку учёта рабочего времени и выплат»:
день недели и дата подставляются автоматически, время и деньги считаются сами,
история хранится в базе и не теряется.

**Ключевые особенности:**
- 🔄 **Облачная синхронизация** — записи телефона долетают до компьютера руководителя без кабелей, облачных дисков и ручного переноса файлов
- 📱 **Android для сотрудника** — приложение «Табель 2.0» на телефоне: рабочий день, обед, доп. работы, премия, штраф, подтверждение получения оплаты
- 💻 **Windows для руководителя** — дашборд только для чтения: список сотрудников, карточки, недели, история, графики, Excel и PDF
- 🔒 **Ролевая модель** — сотрудник видит только свои записи; руководитель — всех своих сотрудников; одно устройство = один человек
- 🧮 **Единое ядро расчётов** — Windows и Android считают деньги одним и тем же зеркальным файлом `timecard_core.py`, округление до рубля выполняется в момент расчёта
- 📴 **Работа офлайн** — телефон пишет в локальную базу без сети и отправляет изменения, когда сеть появляется

## ✨ Возможности

### Для сотрудника (Android)
- ✅ Учёт начала/конца рабочего дня и обеда (время принимается в любом формате: `8`, `8:00`, `0800`, `17.15`)
- ✅ Описание «Объём и качество произведённых работ» через нативный редактор (без багов системной клавиатуры)
- ✅ Дополнительные работы с отдельной ставкой или фиксированной суммой
- ✅ Разовые премии и штрафы
- ✅ Неделя, история по месяцам, итоги
- ✅ Резервное копирование и восстановление (.json)
- ✅ «Поделиться отчётом» — текстовая сводка в WhatsApp / Telegram / почту

### Для руководителя (Windows)
- 📋 Список сотрудников крупными кнопками + серый список архивных с датами (ММ.ГГГГ — ММ.ГГГГ)
- 👀 Карточка сотрудника: вкладки «Неделя», «История», «Настройки»; одобрение дней кликом
- 📊 График выплат и штрафов (неделя/месяц/год, клик по столбику раскрывает подробности)
- 📁 Экспорт табеля в Excel (.xlsx) с формулами и оформлением
- 📄 Печать карточки и графика в PDF (A4, поля 1 см, цветные колонки, жирные зелёные галочки одобрения)
- 🗄️ Архивация/разархивация: архивный сотрудник не может слать новые данные, история остаётся доступной
- 🔁 Перевод сотрудника между руководителями с сохранением истории и привязок устройств
- 🔑 Выпуск и показ токена сотрудника для привязки телефона

### Синхронизация и безопасность
- 🔐 Токен-аутентификация устройств (`bind_device`, `attach_employee`)
- 📡 Очередь команд на сервере (`device_queue`) + GET-опрос `poll_commands`
- 💾 Локальные кэши списков (память 60 с + диск) и пометка «Обновление…» при медленном сервере
- 🚫 Серверная блокировка отправок с устройств архивного сотрудника
- 🔎 SHA-провенанс сборок в описании каждого релиза

## 🏗️ Архитектура

```
┌─────────────────────┐        ┌─────────────────────┐
│  Android «Табель 2.0»│        │  Windows Dashboard  │
│  Kivy, роль: сотрудник│       │  Tkinter, роль: руководитель│
└──────────┬──────────┘        └────────────────────┘
           │ HTTPS: day_updated,          │ HTTPS: list_employees,
           │ payment_*, poll_commands     │ fetch_employee_state, approve_*
           ▼                              ▼
    ┌──────────────────────────────────────────┐
    │   Google Apps Script Web App (code.gs)   │
    │   один URL, константа SYNC_API_URL       │
    └──────────────────┬───────────────────────┘
                       ▼
    ┌──────────────────────────────────────────┐
    │ Google Sheets: employees, accounts,      │
    │ device_queue, timesheet_state,           │
    │ payment_state                            │
    └──────────────────────────────────────────┘
```


**Принципы:**
- Деньги НЕ хранятся на сервере: передаются минуты, ставки, премия и штраф; суммы считает каждое устройство из зеркального ядра `timecard_core.py`.
- `core/timecard_core.py` и `android/timecard_core.py` (а также `sync_client.py`, `reports.py`) совпадают байт-в-байт — иначе платформы начинают считать по-разному.
- Округление до рубля (`round_ruble`) живёт в расчёте ядра, а не в отображении: итог всегда равен сумме колонок.
- Первичные записи редактируются только на телефоне сотрудника; Windows-дашборд — только чтение, одобрение и отчёты.

## 🚀 Установка

### Windows (для руководителя)
1. Откройте страницу [Releases](../../releases) и скачайте ассет **`Tabel-windows.exe`** (один файл, установка не требуется, можно носить на флешке).
2. Запустите файл. Данные программы хранятся в `%APPDATA%\TabelUcheta\`.
3. Зарегистрируйтесь в роли **«Руководитель»** (см. предупреждение в начале страницы).

### Android (для сотрудника)
1. На странице [Releases](../../releases) скачайте ассет **`tabel.apk`**.
2. Перенесите файл на телефон, разрешите «Установку из неизвестных источников», установите.
3. После установки приложение отображается на рабочем столе как **«Табель 2.0»** — это нормальное имя, заданное полем `title` в `buildozer.spec`, оно не обязано совпадать с именем файла.
4. Зарегистрируйтесь в роли **«Сотрудник»** и введите токен, полученный от руководителя.

- **Сервер:** Google-аккаунт владельца проекта для развёртывания Apps Script.

Android (APK)

## ⚠️ APK собирается только на Linux (или WSL на Windows).
```bash
git clone https://github.com/nokirstm/Tabel_W_and_A.git
cd Tabel_W_and_A/android
chmod +x build_apk.sh
./build_apk.sh

Готовый файл: android/bin/tabel-2.0.0-arm64-v8a_armeabi-v7a-debug.apk.
Имя файла собирает Buildozer из трёх полей buildozer.spec: package.name (tabel) + version (2.0.0) + список архитектур (arm64-v8a, armeabi-v7a). Релизный workflow переименовывает его в tabel.apk, а на телефоне приложение называется «Табель 2.0» по полю title. Три разных имени одного и того же артефакта — это штатное поведение, а не ошибка.
Запуск на компьютере (для отладки UI):
```bash
pip install kivy==2.1.0
python android/main.py

Сервер (Google Apps Script, только для владельца проекта)
Исходник code.gs живёт в редакторе Apps Script и не хранится в репозитории.
Правила сопровождения:
Правки вносятся только полной заменой файла code.gs.
После замены публикуется новая версия того же развёртывания — URL обязан оставаться постоянным.
URL развёртывания прописан в клиентах константой SYNC_API_URL.
Проверка здоровья сервера: браузерный GET <SYNC_API_URL>?api_token=…&deviceId=probe-001 должен ответить device not registered.

## 🤝 Вклад в проект

Форкните репозиторий и создайте ветку от windows-sync-v2 или android-backup-v1 (ветка main устарела и не используется).
Перед коммитом прогоните test_core.py и smoke-тесты обеих ролей.
Соблюдайте правила сопровождения:
правки core/ немедленно зеркалятся в android/ байт-в-байт;
правки Windows (app.py, ui_kit.py, reports.py, charts.py) передаются только полными файлами;
code.gs не правится точечными вставками — только полная замена и публикация новой версии развёртывания;
новые apt-пакеты для Buildozer сверяются с эталонным .github/workflows/android.yml.
Откройте Pull Request с описанием симптома, причины и проверки.
